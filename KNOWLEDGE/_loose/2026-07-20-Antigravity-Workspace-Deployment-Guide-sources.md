AI-Workstation Operations Playbook: Lifecycle, Maintenance, and Scaling

1. Strategic Infrastructure Overview

In high-stakes AI engineering, environment stability is not a luxury—it is a prerequisite for reproducible scaling. This workstation utilizes a modular, containerized architecture anchored by the ai-net bridge network and persistent Docker volumes. By employing a disciplined, phased build process and PowerShell-driven orchestration, we decouple the host configuration from the volatile nature of AI model dependencies. This lifecycle ensures that as agent rosters expand and models evolve, the core infrastructure remains resilient and immutable.

The cornerstone of this operational model is Phase Gating. We treat infrastructure as a state machine; we do not move to "Phase N" until "Phase N-1" is verified with raw console output. This rigor prevents the accumulation of technical debt and ensures that failures are isolated and remediated immediately.

Core Rules of Engagement

All engineering operations must adhere to these non-negotiable architectural principles:

* Strict Phase Gating: Infrastructure must be deployed in the exact sequence of Phase 0 through 8. No phase is assumed successful without explicit verification of raw stdout/stderr.
* No Self-Elevation: To maintain explicit control over security contexts, scripts are designed to fail-fast via Assert-Admin rather than attempting to self-elevate.
* Secret Management Integrity: API keys and tokens must never be hardcoded. The Get-OrPromptSecret workflow is mandatory: it probes environment variables first, then local encrypted vaults (.config\secrets\), then interactive prompts.
* Encoding Standards: All script-modified files (JSON, logs, configurations) must be written in UTF-8 without a Byte Order Mark (BOM) to ensure cross-platform compatibility.
* Ground Truth Identification: State must be probed, not guessed. Phase 0 defines the ground truth of the system before any configuration is applied.

5. Systematic Resolution: The @args Inheritance Bug

A high-priority architectural bug exists in the Invoke-Checked @args logic, impacting Phases 5 through 8. This bug silently cripples the modularity of the stack.

Root Cause Analysis

In Start-Services.ps1, Stop-Services.ps1, and Updates.ps1, a local $args array is constructed with -f <file> overlay flags. However, when passed into an Invoke-Checked script block, the @args variable references the script block’s own parameter set, which is always null. Result: Docker Compose executes without overlays, silently ignoring the Task Bus, MCP servers, and Observability services.

Remediation Strategies

Engineers must use the Scope Hoisting fix to ensure overlay files are applied:

* Correct Syntax: Invoke-Checked -Action { docker compose @using:args up -d }
* Manual Fallback: Until the toolchain is fully patched, use the explicit flag string: docker compose -f docker-compose.yml -f docker-compose.taskbus.yml -f docker-compose.mcp.yml -f docker-compose.observability.yml up -d

Operational Risk: "Silent Image Drift"

This bug is most dangerous in Updates.ps1. Because the script block fails to see the overlay flags, it only pulls updates for the base images. The rest of the stack remains on outdated versions, leading to a "silent image drift" that compromises security and performance. Engineers must manually verify that all containers are running the intended image hashes after any update.

6. Data Integrity and Backup Strategies

The Backups.ps1 script is the primary safeguard for stateful AI data and system configurations.

Backup Execution Protocol

The protocol requires Administrative Elevation because it directly accesses protected Docker volume directories.

* Scope: The script exports six volumes (ai-shared-fs, ai-shared-memory, ai-git-repos, ai-nats-data, ai-grafana-data, ai-prometheus-data) and the config\ and docs\ subfolders.
* Exclusion: ai-logs is excluded to optimize storage and speed.
* Format: Archives are timestamped .tar.gz files stored in C:\AI-Workspace\backups\.

Pre-flight Checks

* Volume Existence: If the observability phase has not been run, those volumes will show a "FAILED" status during export. This is expected.
* Disk Capacity: While a fresh backup is roughly 500MB, a populated workspace can exceed 20GB. Confirm host storage before execution.

7. Observability, Health, and Manual Interventions

Scaling an agentic workflow requires real-time insight provided by the OTel → Prometheus → Grafana stack. However, several critical components require human-in-the-loop oversight.

High-Priority Manual Checklist

* Security Gating (The Grafana Footgun): The stack defaults to admin/admin if GRAFANA_ADMIN_PASSWORD is unset in docker.env. This is a critical security vulnerability. You must set a strong password in .env before Phase 7 or change it immediately upon first login.
* Environment Initialization: You must manually create C:\AI-Workspace\docker.env before Phase 4. It must contain, at minimum, a GITHUB_TOKEN and a GRAFANA_ADMIN_PASSWORD.
* MCP Server Resolution: docker-compose.mcp.yml ships with illustrative placeholders (e.g., image: mcp/filesystem-server:latest). You must swap these for real, pulled images before starting Phase 5, or the pull will fail.

NATS JetStream "Task Bus"

The Task Bus subject hierarchy is a schema decision specific to your agent roster.

* Format: agents.[FROM].[TO].[TYPE].[PRIORITY].[REF]
* Example: agents.user.hermes.chat.normal.001
* Consumer Naming: Durable pull consumers must follow the convention:
  * inbox-[agent]-direct (e.g., inbox-hermes-direct)
  * inbox-[agent]-broadcast (e.g., inbox-hermes-broadcast)

The stability of this environment rests on the engineer's commitment to these phased protocols and the application of human judgment during security-sensitive manual steps.
